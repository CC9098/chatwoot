## 本月交付重點

### 1. WhatsApp 穩定性與管理流程大幅加強

呢個月你對 WhatsApp 做咗最完整、最成系統嘅一輪修補，覆蓋 webhook 收訊、channel 對應、重新授權、template 同步、互動訊息 payload 同語系顯示。

#### 1.1 Webhook channel resolution 更穩，降低入站訊息失配風險

你針對 cloud webhook payload 同 channel 對應做咗連續多個修正：

- `31298cc2b`：先將 webhook payload key symbolized，避免 key 型別不一致導致 lookup 失敗。
- `fc9eaf7ee`：把 `phone_number_id` 比對統一轉成字串，避開 numeric/string mismatch。
- `7c6dca9fa`：當 payload metadata 對唔到 channel 時，容許先用 display phone number 落回查找。
- `3b1647b7d`：再補一層用 webhook route `phone_number` 做 fallback，避免 payload 唔完整時直接失敗。
- `3b7502988`：controller 在 enqueue job 前先帶入 `channel_id`，減少 background job 內再解析失準。
- `ee762b931`：Cloud incoming message service 改用 symbolized payload 讀法，收訊流程同 job 前置轉換一致。
- `5222aaa68`：當有效 webhook 再次入到嚟時，自動清除舊的 `reauthorization_required` 狀態，避免 channel 明明已經恢復但仍被鎖死。

#### 1.2 Template 管理由「背景觸發」改成「即時同步 + 即時回報」

你將手動 template refresh 流程由純 enqueue job，改成 controller 直接呼叫 provider sync，令前台按 refresh 後可以即時知道成功或失敗：

- `cc173a0eb`：Cloud / 360dialog provider 新增 `raise_errors` 流程，失敗時會記 log 並丟出 `TemplateSyncError`。
- 同一個 commit 亦同步更新前端 picker，將後端實際錯誤訊息回傳到 UI，而唔係只顯示 generic error。
- `4310493ba`：template 列表保留已批准的 authentication templates，同時仍然過濾未支援類型與 CSAT 模板，令可用模板更貼近實際業務需求。

#### 1.3 WhatsApp Cloud reauthorization 體驗更完整

你將重新授權流程由「勉強可用」補到「實際可重配與切換」：

- `701ae8435`：Cloud inbox 設定頁直接顯示 `Reconfigure` 入口，不再限於特定 source。
- `ccc75c8ec`：reauthorize 不再偷用舊 config，改成重新走 embedded signup event，容許切換 WABA。
- `a9567c197`：reauthorization service 改為持久化新的 `waba_id`，確保重新授權後 provider config 真正更新到最新 business account。
- `b6eb2df53`：處理 `FINISH_WHATSAPP_BUSINESS_APP_ONBOARDING` 事件，補齊 onboarding 完成後的 reauth 流程。

#### 1.4 互動訊息 payload 與語系顯示補齊

你亦處理咗 WhatsApp interactive message 喺實際發送與顯示上的細節問題：

- `0187124db`、`6bdc587fc`、`5fea55bf8`、`1b414871f`：修正 list button label 語系問題，最後收斂為固定中文文案 `請選擇項目`，確保客戶側顯示一致。
- `d4b613e30`：把 interactive action 由 JSON string 改回 object payload，令按鈕與 list 訊息格式更符合 provider 預期。

#### 1.5 呢條主線嘅實際價值

- 減少 WhatsApp Cloud webhook 入站訊息食唔到或錯配 channel 的機會。
- 降低重新授權後仍維持錯誤狀態、或者切換 WABA 失敗的營運風險。
- 令 template refresh 變成可即時驗證、可即時報錯的操作。
- 改善中文市場實際客戶看到的互動訊息體驗。

### 2. 私密筆記 Todo 由文字備忘升級成可操作工作流

呢部分係你今個月最完整嘅 feature delivery，而且前後端都做齊。

#### 2.1 Private note checklist inline 化

- `3f1517852`：你為 private note 加入 checklist 能力。
- 新增 `privateNoteTodoHelper.js` 去解析 markdown todo line、計 progress、切換勾選狀態。
- 訊息 bubble 新增 `PrivateNoteChecklist.vue`，可以直接在對話視窗內勾選 todo。
- `messages_controller.rb` 新增 private note update path，允許只更新 private note content，而唔會走 API inbox status update 限制。
- ReplyBox 新增一鍵插入 Todo 項模板，降低 agent 建立任務清單門檻。

#### 2.2 Shared Todos overview 做成獨立工作台

- `cb0922c67`：你再進一步唔只係做 inline checklist，而係拉高到 account 級別 overview。
- 後端新增 `Api::V1::Accounts::TodosController`，會掃描可訪問 conversations 內所有含 todo pattern 的 private notes。
- 前端新增 `TodoList.vue` / `TodoView.vue`、新 route、sidebar 入口、mobile launcher 入口。
- 支援 summary cards、搜尋、show completed、從 todo 直接 deep-link 到 conversation 及指定 message。
- 支援直接在 overview 內勾選 / 取消勾選，變成跨會話工作台，而唔只係單一對話內備註。

#### 2.3 呢條主線嘅實際價值

- 將 agent 私密筆記由靜態文字升級成可追蹤、可篩選、可集中查看的 todo system。
- 提升 handoff、跟進、內部協作效率。
- 對高 volume support inbox 特別有價值，因為待辦不再散落於各 conversation。

### 3. Captain 自動回覆邏輯收緊，避免打斷人工跟進

- `e4cf8c9c9`：你喺 enterprise overlay 補咗一條關鍵規則，**只有超過 72 小時無互動**，先視為 Captain 可以接手的新 round。
- 如果同一 contact 在 72 小時內仍有往來，即使 conversation 係 pending，系統會優先 reopen 俾人手跟進，而唔係再自動排 Captain response。
- spec 同步補上 follow-up / new conversation within 72h 兩種場景，確保規則有被驗證。

#### 呢條主線嘅實際價值

- 避免 AI assistant 喺人手跟進中途插嘴。
- 將「同一輪跟進」同「新一輪對話」切分得更清楚。
- 對服務品質與 agent ownership 都係加分。

### 4. 新對話 compose 與 continuity inbox 選擇更可靠

#### 呢條主線嘅實際價值

- 令 website continuity via email 場景可以真正運作。
